## Brauzerdə yoxlananlar

- Məhsul siyahısı → məhsul detalı → səbətə əlavə. Sayğac 0 → 1 → 2 yeniləndi.
- 20 ₼ məhsul: 1 ədəd + 4 ₼ çatdırılma = 24 ₼; 2 ədəd + 4 ₼ = 44 ₼; mağazadan götürmə = 40 ₼.
- Reload-dan sonra məhsul və miqdar saxlandı. Çatdırılma seçimi reload-dan sonra standart üsula qayıdır; bu, məhsul səbətinin saxlanmasına mane olmur.
- Səbətdən silmə təsdiqi açıldı, yalnız QA üçün əlavə edilmiş məhsul silindi; əvvəlki boş səbət bərpa edildi.
- Printer favoriti əlavə edildi, `/favorites` siyahısında göründü, silinib reload ilə yoxlandı. Əvvəldən mövcud çamadan favoriti saxlandı.
- Minimum 500, maksimum 100: düzgün aralıq xətası göstərildi. 30–40 ₼: yalnız 39,50 və 30 ₼ məhsullar gəldi. URL və reload filtr nəticəsini qorudu.
- Mövcud olmayan axtarış: aydın nəticəsiz vəziyyət göstərildi.
- Mövcud QA alıcı sessiyası ilə kabinet render edildi; sifariş/ünvan/profil dəyişdirilmədi.
- Qonaq qeydiyyatı: boş form native validation ilə dayandı; ad, soyad, email, telefon və iki şifrə sahəsi invalid oldu. Yeni hesab yaradılmadı.
- Razılaşma sətrinə klik sənədi açdı; sənədin sonuna sürüşdürülmədi və hüquqi razılıq qəbul edilmədi.
- Kateqoriya dialogu `aria-modal=true`, focus içəridə; Escape bağladı və focus açan düyməyə qayıtdı.
- Səbət və qeydiyyat: **320, 375, 390, 430, 768, 1024, 1440 px** enlərdə üfüqi daşma yoxdur.
- Səbətdə read-only DOM audit: adsız görünən button 0, labelsız input/select/textarea 0, alt atributu olmayan img 0, yüklənmiş qırıq img 0. Bu, tam WCAG/axe sertifikasiyası deyil.

## Tapılıb düzəldilənlər

1. **Qonaq birbaşa WhatsApp sifariş niyyəti üçün rate-limit yox idi.** Yeni test bunu göstərdi. `guest_checkout` bucket-i ilə 15 dəqiqəlik limit DB order yazısından əvvəl tətbiq edildi. Mövcud bucket/RPC sxemi dəyişdirilmədi.
2. **WhatsApp note uzunluğu serverdə yoxlanmırdı.** 1000 simvoldan uzun qeyd artıq DB mərhələsindən əvvəl rədd edilir.
3. **Adi qonaq checkout-u rate-limit yazılmasının bloklandığını nəzərə almırdı.** `recordAuthRateLimitAttempt` nəticəsində blok/xəta olduqda checkout indi yazı yaratmadan dayanır. Yeni test hər iki guest axının fail-closed davranışını təsdiqləyir.

Qiymət saxtalaşdırma testi göstərir ki, action atomic checkout RPC-yə yalnız productId, miqdar və variant seçimlərini ötürür; client qiyməti/storeId authority kimi istifadə olunmur. RPC-nin faktiki maliyyə nəticəsini yaratmaq üçün bu audit canlı order göndərməyib.

## Qalan məqamlar və sınaq sərhədləri

- **P2 — Tam daxili UI tərcüməsi bitməyib:** rus dili ilə qeydiyyat forması və kabinetdə bəzi əvvəlki mətnlər Azərbaycanca qalır. Yeni public header/home/footer/default categories işləyir. Satıcı məhsulunun orijinal mətni ilə platforma label-ları ayrı qiymətləndirilməlidir.
- **P2 — Atomik rate-limit:** hazırkı SELECT→UPSERT sayğacı paralel cəhdlərdə artım itirə bilər. Bu tur DB miqrasiyası etmədi; əvvəlki security report-da atomik RPC təklifi var.
- **P2 — CSP nonce və trusted proxy/origin firewall:** əvvəlki auditdə qeyd olunan sərtləşdirmələr ayrıca konfiqurasiya işidir.
- Real alıcı/satıcı/admin hesabları ilə tam yeni qeydiyyat→email təsdiqi→məhsul yazısı→sifariş→refund/payment ssenarisi aparılmadı. Mövcud kod testləri bu ssenarilərin bir hissəsini mock/test DB ilə örtür.
- Kart provayderi bu layihədə inteqrasiya edilməyib; uğurlu kart ödənişi/webhook testini “keçdi” saymaq olmaz.
- Yeni mesaj, rəy, kütləvi bildiriş, email/SMS göndərişi və real məhsul importu canlı istifadəçilərə təsir etməmək üçün icra olunmadı.
- Lighthouse, axe və ayrıca Playwright runner bu icrada işlədilməyib. Brauzer ssenariləri CUA-nın Playwright locator-ları ilə icra edildi; HTTP performans və əsas DOM audit ayrıca verilib.
- Root tətbiqdə ESLint script/config yoxdur. TypeScript/build/test keçib; ESLint nəticəsi yalnız `frontend/` prototipinə aiddir.
